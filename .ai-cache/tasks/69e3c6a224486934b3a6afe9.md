# Анализ задачи: [Tech Debt] Экспорт PDF как текст, а не растр

## 1. Что нужно сделать

**Суть проблемы:**
- `src/composables/usePdfExport.ts` клонирует DOM превью и экспортирует через `html2canvas` → `jsPDF.addImage`
- Результат: растровое изображение (картинка), а не текстовый PDF
- UI в `stores/locale.ts` (поле `pdf.hint`) обещает пользователю, что PDF-метаданные и резюме внутри документа помогают ATS-системам находить резюме
- **В реальности:** ATS без текстового слоя может прочитать только встроенные метаданные (Title/Subject/Keywords/Author), а основное содержание резюме для них невидимо
- Контраст: TECH-LEAD.md явно фиксирует это как ограничение — "Экспорт растровый (не текстовый): поисковый слой и ATS-читаемость обеспечиваются только встроенными метаданными"

**Три варианта решения (на выбор):**
1. Переход на `jsPDF.html()` с собственной реализацией пагинации через `measurePagedLayout` (чтобы не дублировать логику)
2. Замена на `pdf-lib` + писание собственного текстового рендерера на основе доменной модели `ResumeData` (более гибко, но трудозатратнее)
3. **Продуктовое решение:** переформулировать UI-копирайт в `pdf.hint` так, чтобы не обещать ATS-дружественность и не вводить пользователя в заблуждение

## 4. План действий

### Вариант А: Техническое решение (jsPDF.html)
- Изучить возможности `jsPDF.html()` и его параметры пагинации
- Синхронизировать результат с логикой `measurePagedLayout` из `utils/pagination.ts` (ключевой инвариант: единственный источник разбиения на страницы)
- Переписать `usePdfExport.ts` с отменой html2canvas, но сохранив встроенные метаданные
- Протестировать пагинацию на многостраничных резюме

### Вариант Б: Техническое решение (pdf-lib + собственный рендерер)
- Разработать сериализацию `ResumeData` → текст в зависимости от активного шаблона (`ResumePreview` или планируемый `ModernResumePreview`)
- Реализовать текстовый рендерер с поддержкой стилей (шрифты, отступы, разрывы страниц)
- Встроить метаданные из `PdfMetaStore`
- Сложнее, но даёт полный контроль над форматом

### Вариант В: Продуктовое решение
- Переформулировать `pdf.hint` в `stores/locale.ts`, чтобы не обещать ATS-читаемость
- Указать, что PDF — это визуальное представление резюме для человека, и для ATS нужны другие инструменты (LinkedIn, HH и т.д.)
- Быстрое решение, но не закрывает расхождение между обещанием и реальностью на техническом уровне

## 5. Контекст из документов

### Из PM.md
- Продукт — одноразовый сеансовый инструмент (открыл → заполнил → скачал → закрыл)
- Ценность для пользователя: PDF со встроенными метаданными — маленький шаг в сторону ATS-дружественности
- Ограничение: "Только PDF на выходе", экспорт растровый (из канваса), а не текстовый

### Из TECH-LEAD.md
- `usePdfExport.ts`: "Клонирует узел превью в оффскрин-контейнер, растеризует через html2canvas (scale 2) и нарезает канвас в jsPDF по pageStarts из measurePagedLayout. Экспорт растровый (не текстовый): поисковый слой и ATS-читаемость обеспечиваются только встроенными метаданными (Title/Author/Subject/Keywords)."
- Ключевой инвариант: `utils/pagination.ts: measurePagedLayout` — единственный источник разбиения на страницы. Превью и экспорт оба его потребляют; повторная реализация в экспортёре запрещена.
- Стек: `html2canvas 1.4 + jspdf 4 (растровый экспорт)`
