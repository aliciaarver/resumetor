## Что нужно доделать (❌)

### 1. Критическая ошибка — консоль (#10 QA comment 1)
**Файл:** `TestCaseDebugEmpty.vue`  
`toRefs` и `unref` используются без импорта. Импортирован только `computed` из `#imports`.

### 2. Лейблы фильтров (#4 QA comment 2)
**Файл:** `useTestCaseDebug.ts` — `filterOptions`

| Было | Нужно |
|------|-------|
| "Весь список" | "Все" |
| "Есть блокировка" | "Заблокированные" |
| "Нет блокировки" | "Разрешённые" |

Также добавить логику `disabled` (когда 0 результатов в категории) + tooltips.

### 3. Статус-теги в карточке (#5 QA comment 2)
**Файл:** `TestCaseResultCard.vue`  
Метод `getTemplateLabel` сейчас возвращает из `templateTypesById` → "Геоблок", "Нет блокировки".  
Нужно: на основе `displayTypeId`:
- `EDisplayType.Blocked` → **"Заблокирован"**
- иначе → **"Разрешён"**

### 4. Поле "Вид" (#6 QA comment 2)
**Файл:** `TestCaseResultCard.vue`  
Новое поле, показывается только для заблокированных. Определяется по `templateId`:
- `templateId === 1` (Геоблок) → "Без авторизации"
- `templateId === 2` (Геоблок с авторизацией) → "С авторизацией"

### 5. Тултипы таббара (#6 QA comment 1)
**Файл:** `TestCaseDebugFilter.vue`  
Добавить `ATooltip` для disabled-кнопок:
- "Заблокированные" → "Нет заблокированных стран с указанными параметрами"
- "Разрешённые" → "Нет разрешенных стран с указанными параметрами"

### 6. Название кнопки "Desktop" (#3 QA comment 2)
**Файл:** `TestCaseParameters.vue`  
"Desktop-версия" → **"Desktop"** (для одинаковой высоты кнопки при разных разрешениях)

### 7. Кнопка "Проверить" (#5 QA comment 1)
**Файл:** `TestCaseDebug.vue` + `test-case-debug.scss`  
По дизайну кнопка должна быть внизу всей страницы, не только левой колонки.

### 8. Центрирование картинки (#4 QA comment 1)
**Файл:** `test-case-results.scss` / `test-case-debug-empty.scss`  
Картинка empty state в правом блоке не центрирована.

### 9. Пустой блок (#1, #2 QA comment 2)
**Файл:** `TestCaseResults.vue` / `test-case-results.scss`  
- Убрать пустой блок снизу при открытии раздела
- Растянуть по ширине страницы

### 10. Адаптивность (#9 QA comment 1)
**Файлы:** CSS-файлы  
Не адаптировано под разрешения 1366×768 и 1024×768. Расположение и размер не соответствуют макету.

## Figma — ключевые детали

### Форма (левая колонка)
- Заголовок страницы: "Тестирование и отладка"
- Subtitle формы: "Укажите параметры для запуска теста"
- Поля: Проект, Страны, Язык, Тип клиента (Desktop-версия / Мобильный)
- Раздел "Дополнительные параметры": Домен (`Введите домен`), URL (`Введите URL`), Регион (`Код в формате AZ`), Город (`Код в формате AZ`)
- Тест блокировки бота: Пользователь / Бот → при Бот показывается дропдаун "Тип бота"
- Кнопка "Проверить" — внизу **всей страницы**

### Результаты (правая колонка)
- Заголовок: "Результат теста" + кнопка "Скачать"
- Таббар: **Все / Заблокированные / Разрешённые**
  - Тултип на "Заблокированные" (disabled): "Нет заблокированных стран с указанными параметрами"
  - Тултип на "Разрешённые" (disabled): "Нет разрешенных стран с указанными параметрами"
- Карточка: Страна, Статус-тег (Заблокирован/Разрешён), **Вид** (С авторизацией/Без авторизации), Причина блокировки
- Empty: "Тут пока пусто" / "Укажите параметры для запуска теста"
- No Result: "Информация не найдена" / "Попробуйте задать другие параметры для тестирования"

### Локальные компоненты
- Status tag: `Block=On` → "Заблокирован" (красный), `Block=Off` → "Разрешён" (зелёный)
- Auth tag: `With auth` → "С авторизацией", `Without auth` → "Без авторизации"
