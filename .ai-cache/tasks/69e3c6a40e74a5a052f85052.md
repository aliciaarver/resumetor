## 1. Что нужно сделать по задаче

Нужно решить две связанные проблемы в коде парсера PDF:

### Проблема 1: Типизация для `pdfjs-dist`

В файле `src/composables/useResumeParser.ts` используются `any` типы для объектов из библиотеки `pdfjs-dist`:
- Строка 191: параметр `pdf` в `extractHeaderPersonalInfo(pdf: any)`
- Строка 199: итерируемый `annotation` тип в `.filter((annotation: any)`
- Строка 212: переменная `annotation` в `.map((annotation: any)`
- Строка 233: параметр `pdf` в `extractPdfMetadata(pdf: any)`

Согласно TECH-LEAD.md (раздел 4), `pdfjs-dist` обрабатывает внешние файлы, поэтому потеря типов здесь особенно критична для надёжности.

Требуется подключить типы из пакета `pdfjs-dist` (например, `PDFDocumentProxy` для pdf-документа, `AnnotationData` для аннотаций) и заменить все `any` на конкретные типы.

### Проблема 2: Дублирование функции `detectLinkLabel`

В том же файле (строки 224-231) есть функция `detectLinkLabel`, которая определяет тип социальной ссылки (Email, GitHub, LinkedIn, Telegram, Link) на основе URL.

В параллель в файле `src/utils/socialLinks.ts` (строка 7) существует функция `normalizeSocialLinkLabel`, которая делает по сути то же самое — преобразует строковый лейбл в типизированное значение из `SOCIAL_LINK_TYPES = ['Email', 'LinkedIn', 'Telegram', 'GitHub', 'Link']`.

Текущая дублированная логика создаёт точки несогласованности: если в будущем добавить новый тип социальной ссылки, придётся обновлять оба места. Требуется унифицировать подход.

## 4. Что планируется сделать

1. **Подключить типы `pdfjs-dist`:** Добавить импорт типов из пакета `pdfjs-dist` (например, `import type { PDFDocumentProxy, PDFPageProxy, AnnotationData } from 'pdfjs-dist/types'`).

2. **Заменить `any` на конкретные типы:**
   - `extractHeaderPersonalInfo(pdf: any)` → `extractHeaderPersonalInfo(pdf: PDFDocumentProxy)`
   - `annotation: any` → `annotation: AnnotationData` (или аналогичный тип из `pdfjs-dist`)
   - `extractPdfMetadata(pdf: any)` → `extractPdfMetadata(pdf: PDFDocumentProxy)`

3. **Унифицировать логику определения типа ссылки:**
   - Либо переместить функцию `detectLinkLabel` из `useResumeParser.ts` в `src/utils/socialLinks.ts` и переиспользовать через `normalizeSocialLinkLabel`.
   - Либо убрать `detectLinkLabel` и заменить её вызов (строка 215: `label: detectLinkLabel(url)`) на вызов функции, которая бы использовала ту же логику через `socialLinks.ts`.
