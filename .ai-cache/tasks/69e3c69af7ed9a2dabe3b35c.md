# PM-анализ задачи: XSS через протокол в URL соц-ссылок

## 1. Что нужно сделать

Устранить уязвимость XSS при вводе вредоносных протоколов в URL социальных ссылок.

**Сценарий:** Пользователь вводит в поле ссылки значение вроде `javascript:alert(1)` вместо обычного URL. При клике по ссылке в предпросмотре резюме или в экспортированном PDF может выполниться произвольный JavaScript-код.

**Что нужно гарантировать:** Только безопасные протоколы (`http://`, `https://`, `mailto:`, `tel:`) должны быть разрешены. Все остальные схемы — либо отклоняться, либо префиксоваться `https://`.

## 4. План действий

1. **Создать allow-list безопасных протоколов** в `src/utils/socialLinks.ts`:
   - `http://`, `https://` — веб-ссылки
   - `mailto:` — email
   - `tel:` — телефон
   
2. **Обновить функцию `buildSocialLinkHref`** (строки 27, 31):
   - Проверять схему входного URL
   - Если она в allow-list — использовать как есть
   - Иначе — либо отбросить, либо префиксовать `https://`

3. **Добавить unit-тесты** на вредоносные входы:
   - `javascript:alert(1)`
   - `data:text/html,...`
   - `vbscript:`
   - `file://`

4. **Проверить `getSocialLinkDisplayText`** — убедиться, что он тоже безопасен и не рендерит HTML как код.
