## 3. Figma — что за макет

Файл "Тестирование и отладка" (fileKey EATFzY0oj8Sozcd00He7A0), нода 161:4342.

ВНИМАНИЕ: Это макет GRS (геоблокировки), а не RDS. Используется как основа для структуры UI, но терминология геоблокировок заменяется на терминологию редиректов.

### Основная структура страницы:

Левая колонка — форма:
- Раздел 1: Проект, Страны, Язык, Тип клиента (Desktop / Мобильный)
- Разделитель
- Раздел 2: Домен, URL/Путь, Регион, Город, Тест блокировки бота (Пользователь / Бот), Тип бота
- Кнопка «Проверить» — ВНИЗУ ВСЕЙ СТРАНИЦЫ (не только левой колонки!)

Правая колонка — результаты:
- Заголовок "Результат теста" + кнопка "Скачать"
- Таббар: Все / Заблокированные / Разрешённые (в GRS-версии — в RDS нужна своя терминология)
- Карточки результата: страна, статус-тег, причина, JSON-аккордеон
- Empty state (иконка папки + текст)
- No result state (иконка папки с лупой)

## 4. Текущее состояние кода

### Что реализовано:
- TestCaseDebug.vue — двухколоночный layout (форма + результаты)
- TestCaseParameters.vue — форма с доменом, странами, языком, UserAgent, cookies
- TestCaseResults.vue — правая колонка с header, фильтр, список карточек
- TestCaseResultsCard.vue — карточка результата (страна, индикаторы, JSON-коллапс)
- TestCaseDebugFilter.vue — таббар фильтрации
- TestCaseDebugEmpty.vue — empty/no-result состояния (уже с правильными иконками)
- TestCaseDebugIndicators.vue — индикаторы редиректа (код, URL, правила)

### Что НЕ соответствует ожиданиям тестировщика:

1. formConfig.ts: userAgentClientMobile.label = 'Мобильный клиент' → нужно «Тип клиента»
2. TestCaseParameters.vue:135: Кнопка «Desktop-версия» → нужно «Desktop»
3. TestCaseParameters.vue: Актуализатор вложен внутрь <AFormItem> для домена — нужно выделить отдельным блоком
4. TestCaseParameters.vue:85-88: actualizerMobile использует <ASwitch> (toggle), а не radio — возможно не отображается ожидаемо; тестировщик говорит что поле отсутствует
5. TestCaseDebug.vue:21-29: Кнопка «Проверить» внутри левой колонки — нужно вынести вниз всей страницы
6. test-case-results.scss: __list имеет max-height: 1250px и overflow-y: auto — нужен scroll внутри контент-враппера
7. test-case-debug.scss: нет медиазапросов для 1366 и 1024
8. TestCaseDebug.vue: возможен «пустой блок» — нужно растянуть по ширине
9. TestCaseDebugFilter.vue: нет тулт ипов на disabled-вкладках
10. Верстка правого блока: тестировщик показал скриншоты image3.png, image7.png — конкретная проблема пока не видна без скриншотов
