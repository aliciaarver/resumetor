# Стили

## Базовые правила
- Следуй токенам и палитре, зафиксированным в `TECH-LEAD.md` проекта (дизайн-токены, переменные темы). Новые цвета не вводи произвольно.
- CSS-фреймворки (Tailwind/Bootstrap и т. д.) используй только если это принято в проекте. Иначе пиши руками.
- `box-sizing: border-box` — дефолт.
- Стили компонента scope'ь механизмом фреймворка (`<style scoped>`, CSS Modules, styled-components — что в проекте).

## Повторяющиеся значения → CSS-переменные, повторяющиеся блоки → миксины

Если один и тот же цвет, размер, радиус, тень или отступ встречается в 3+ местах — вынеси в CSS custom property (`--color-accent`, `--radius-md`, `--shadow-card`), а не копируй значение по компонентам. Источник правды — токены из `TECH-LEAD.md` проекта. Переменные задавай на `:root` (или на уровне темы), используй через `var(--...)`.

Если повторяется не значение, а **блок стилей** (например, стилизация инпута, «карточка с границей», truncate на N строк, типовая анимация появления) — вынеси в миксин, если в проекте есть препроцессор (SCSS `@mixin`/`@include`, Less, Stylus). Если препроцессора нет — используй CSS-классы-утилиты, `@layer` или композицию (в Vue — `<style scoped>` в дочернем с общим классом, или общий `assets/styles/utilities.css`, подключённый через `@import`).

Правило меры: **3+ повторений — рефакторим**. Один-два раза не повод городить абстракцию.

### Ложная общность
Рефакторим только если у повторяющегося значения **общая семантика** — это один и тот же токен (цвет бренда, базовый радиус, шаг сетки), который обязан меняться везде одновременно. Если значения совпали случайно (`padding: 16px` у кнопки и `gap: 16px` в гриде — разные сущности, просто число одно), переменную не вводим: склеивание несвязанных мест через общий токен ломает их при первой же правке. Сомневаешься «это один смысл или два?» — оставляй как есть, дублирование честнее ложной общности.

### Примеры
- Цвет `#89b4fa` в 5 местах → `--color-accent-blue: #89b4fa;`, затем `color: var(--color-accent-blue)`.
- Одинаковая стилизация кнопок «read/write/primary» → миксин `@mixin btn-outline($color)` или общий класс `.btn-outline` + модификаторы.
- Одинаковый `text-overflow: ellipsis; overflow: hidden; white-space: nowrap;` в нескольких местах → класс-утилита `.truncate` или миксин `@mixin truncate`.

Новые переменные и миксины фиксируй в соответствующем файле стилей (`assets/styles/tokens.css`, `assets/styles/mixins.scss`, и т. п. — смотри соглашения проекта).

## Шрифты — только через компонент `Typography`

Любой текст в интерфейсе оборачиваем в компонент `Typography` (`<Typography variant="..." color="...">...</Typography>`). Этот компонент — единственный источник правды по шрифтам: размер, начертание, line-height, letter-spacing, семейство, набор вариантов (`h1`, `h2`, `body`, `caption`, и т. д.) и допустимые цвета живут внутри него.

- В компонентах **руками не пишем** `font-size`, `font-weight`, `font-family`, `line-height`, `letter-spacing` — ни в `<style>`, ни инлайном, ни через утилитарные классы. Нужен другой стиль шрифта — выбираем существующий `variant` или добавляем новый внутрь `Typography`.
- Цвет текста и вариант передаём **пропсами** (`variant`, `color`, при необходимости `as`/`tag`, `align`, `weight` если такой проп предусмотрен), а не переопределением CSS снаружи.
- Если компонента `Typography` в проекте ещё нет — **создай его** перед тем, как верстать текст. Положи в общий `components/ui/Typography.vue` (или туда, где в проекте лежат базовые UI-компоненты), завяжи варианты на токены из `TECH-LEAD.md`.
- Исключения — только системные элементы, которые не являются «текстом интерфейса» (например, `<input>`, где шрифт наследуется от родителя). Заголовки, подписи, описания, кнопочный текст, ошибки, плейсхолдеры-как-подписи — всё через `Typography`.

## CSS, а не JS/TS для визуальных задач

Если задачу можно решить стилями — решай стилями. JS/TS подключай только когда CSS физически не справляется.

Примеры, где CSS сильнее:
- **Обрезка текста с троеточием** — `text-overflow: ellipsis` + `overflow: hidden` + `white-space: nowrap` + `max-width`. Не вычисляй и не подрезай строки в скрипте — это прячет полное значение от DOM (ломает поиск, селект, a11y, `title` на hover), и ведёт себя по-разному при смене шрифта.
- **Показ/скрытие элементов** по hover/focus/состоянию родителя — псевдоклассы `:hover`, `:focus-within`, `:has()`, а не обработчики событий.
- **Адаптив** — media queries, контейнерные запросы, `clamp()`, `min/max()`, а не `window.resize`.
- **Анимации и переходы** — `transition`/`@keyframes`, а не `setInterval` с ручным изменением стилей.
- **Выравнивание, grid, truncate на N строк (`-webkit-line-clamp`), выделение активного пункта** — чисто CSS.

Критерий простой: данные не должны деформироваться в угоду отображению. JS меняет данные, CSS меняет их вид. Если что-то можно написать в `.css/scoped style` — пиши туда.
