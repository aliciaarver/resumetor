# Производительность и качество

Универсальные правила + специфика Vue и React. Глубокие оптимизации включаем **по факту проблемы**, а не превентивно: сначала метрика, потом правка. Оптимизация «по ощущениям» обычно ухудшает читаемость и не двигает цифры.

## Универсально (любой фреймворк)

### Замер
- DevTools → Performance (flamegraph, Paint, Layout Shift), Lighthouse, WebPageTest.
- Следи за ключевыми метриками: **LCP**, **INP** (пришёл на смену FID), **CLS**, **TBT**, размер JS-бандла.
- Настрой CI-бюджеты на бандл (`size-limit`, `bundlewatch`) и Lighthouse CI там, где это оправдано.

### Загрузка
- **Код-сплит по роутам** — дефолт. Динамический импорт страниц вместо одного жирного бандла.
- **Lazy-load тяжёлых нестраничных компонентов**: редакторы кода/текста, карты, графики, тяжёлые модалки.
- Грузи критический CSS инлайном, остальное — отложенно. `font-display: swap`, preconnect/preload для первичных шрифтов.
- Следи за размером бандла: `rollup-plugin-visualizer` / `webpack-bundle-analyzer`. Жирные зависимости заменяй (moment → date-fns/dayjs) или грузи лениво.

### Рендер
- Избегай длинных синхронных вычислений в main thread. Тяжёлое — в Web Worker или разбивать через `requestIdleCallback`/`scheduler.postTask`.
- **Виртуализация** длинных списков (`@tanstack/virtual`, `vue-virtual-scroller`) от ~100 элементов.
- Явные `width`/`height` у медиа — чтобы не было CLS.

### Сеть
- Дебаунс/тротлинг для поиска и «тяжёлых» инпутов.
- Клиентский кеш серверного состояния (TanStack Query, SWR, Pinia Colada).
- Отмена устаревших запросов через `AbortController`.
- Прелоад данных для следующего шага, если ясен маршрут пользователя.

### Ассеты
- Изображения: корректные размеры (`srcset`, `sizes`), современные форматы (`webp`/`avif`), `loading="lazy"` для ниже фолда.
- Иконки: инлайн SVG или спрайт. Не тащи icon-фонт ради 5 иконок.
- Шрифты: ограниченный набор начертаний, subset под латиницу/кириллицу.

## React

### Ре-рендеры — главный источник тормозов
- Не создавай новые объекты/массивы/функции в JSX props без нужды — они ломают мемоизацию дочерних компонентов.
- `React.memo` — для элементов больших списков и компонентов под «горячим» родителем. Не оборачивай всё подряд: сравнение пропсов тоже стоит.
- `useMemo`/`useCallback` — когда есть **измеренный** дорогой расчёт или стабильная ссылка нужна мемоизированному ребёнку. Просто так не навешиваем.
- React 19+ / React Compiler (если включён в проекте) — большую часть мемоизации делает сам, тогда ручные `useMemo`/`useCallback` не добавляем без причины.

### Хуки
- Вызываем только на верхнем уровне компонента/другого хука.
- Массив зависимостей — полный, без ручного «обмана» линтера. Нужно исключить — переосмысляй логику, а не подавляй правило.

### Состояние
- **Серверное состояние** — TanStack Query / SWR. Не тащи его в Redux.
- **Клиентское глобальное** — Zustand / Redux Toolkit / Jotai (выбор в `TECH-LEAD.md`).
- **Локальное** — `useState`/`useReducer`.
- Контексты разделяй по частоте обновлений: один «жирный» `AppContext` с часто меняющимся значением перерисует всё поддерево.

### Код-сплит
- `React.lazy` + `<Suspense>` для страниц и тяжёлых компонентов.
- `loadable-components` если нужен SSR с async-чанками.

### Формы
- `react-hook-form` с uncontrolled inputs — меньше ре-рендеров, чем полностью controlled.

### Списки
- Стабильные `key` (id), никогда не индекс массива — ломает переиспользование и анимации.

## Vue 3

### Реактивность
- `ref` для примитивов и одиночных значений; `reactive` для связанных объектов. Не смешивай ради смешения.
- `shallowRef` / `shallowReactive` / `markRaw` для больших структур, где глубокая реактивность не нужна (таблицы на тысячи строк, инстансы сторонних библиотек).
- Не теряй реактивность при деструктуризации — используй `toRefs` / `storeToRefs` (для Pinia).

### Производные значения
- Производное значение — **всегда `computed`** (кешируется). Функция в шаблоне пересчитывается каждый рендер.
- `watch` с явными источниками предпочтительнее `watchEffect`: яснее, когда и почему срабатывает.

### Шаблон
- **`v-memo`** — для больших списков, где элементы редко меняются.
- **`v-show` vs `v-if`**: `v-show` для часто переключаемых (держит DOM), `v-if` для редких/тяжёлых веток.
- `v-for` + стабильный `key` (id), не индекс.
- Не пиши выражения с сайд-эффектами в шаблоне.

### Код-сплит
- `defineAsyncComponent` + `<Suspense>` для тяжёлых компонентов.
- Роутер — асинхронные компоненты страниц по умолчанию.

### Состояние
- **Pinia** — стандарт для глобального стора. Тащим в стор только действительно глобальное; локальное живёт в компоненте или composable.
- Серверное состояние — Pinia Colada / TanStack Query for Vue / VueUse `useFetch` с кешом.

### Мелочи
- Шаблонные рефы типизируй: `const el = ref<HTMLDivElement | null>(null)`.
- `provide`/`inject` — только с `InjectionKey<T>` для типизации.

## Что не делаем
- Не оптимизируем без метрик. Нет цифры до/после — нет оптимизации.
- Не засоряем код `memo` / `useMemo` / `shallowRef` превентивно.
- Не делаем код-сплит мелких компонентов (кнопок, иконок) — оверхед загрузки больше выигрыша.
- Не отключаем Vue/React DevTools в dev-сборке.
- Не используем `eval` / `new Function` / inline-скрипты для «ускорений».
