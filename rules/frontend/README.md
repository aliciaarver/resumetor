# Frontend Rules (универсальные)

Правила применяются ко всем проектам, которыми управляет дашборд. Стек, фреймворк, палитра, тест-инструменты **конкретного проекта** — в `TECH-LEAD.md` (или `FRONTEND.md` / `TESTING.md`) этого проекта.

## Базовое
- **TypeScript обязателен** независимо от фреймворка. Детали — в [`architecture.md`](./architecture.md).
- **Проекты на Vue и React** строятся по **Feature-Sliced Design**. Детали — там же.

## Разделы

| Файл | О чём |
|---|---|
| [`architecture.md`](./architecture.md) | Структура компонентов, TypeScript, FSD, composables/hooks |
| [`styles.md`](./styles.md) | Токены, CSS-переменные, миксины, `Typography`, CSS vs JS |
| [`api.md`](./api.md) | Работа с API: auth-слой, ошибки, загрузка, URL |
| [`performance.md`](./performance.md) | Оптимизация: универсальные правила + специфика Vue и React |
| [`testing.md`](./testing.md) | Что тестируем, что нет, минимум для задачи |

## Что не делать (cross-cutting)
- Игнорировать ошибки типизации / глушить через `@ts-ignore`, `any`, `// eslint-disable` без причины.
- Коммитить без прохождения type-check'а проекта.
- Хардкодить URL или конфиги.
- Отключать или пропускать падающие тесты, «чтобы собралось».

## Как читать
- Перед созданием/рефакторингом компонента — `architecture.md`.
- Перед правкой вёрстки — `styles.md`.
- Перед работой с сетью — `api.md`.
- При жалобах на тормоза или перед релизом — `performance.md`.
- Перед сдачей — `testing.md` и чек-лист из `rules/qa.md`.

Если замечаешь, что правило устарело или неполно — правь соответствующий файл. Правила, специфичные для одного проекта, пиши в `TECH-LEAD.md` / `FRONTEND.md` этого проекта, не сюда.
