# Тесты

Конкретные инструменты (Vitest, Jest, Playwright, Cypress, …) указаны в `TECH-LEAD.md` / `TESTING.md` проекта. Общее правило:

- **Обязательны** для:
  - composables/hooks/utils с логикой,
  - критических пользовательских сценариев (авторизация, платежи, формы с валидацией),
  - баг-фикса (регрессионный тест, воспроизводящий баг до правки).
- **Не нужны** для:
  - тривиальной вёрстки без логики,
  - разовых визуальных правок.
- **Минимум** для задачи — happy path + ключевые edge cases (пустые данные, ошибка API, длинные строки). Процент покрытия не самоцель.
- Перед сдачей тесты должны быть зелёными локально. Падающий тест — чинить, не скипать и не отключать.

## Что проверяем в компоненте
- Рендер с разными пропсами — ключевые ветки, не все комбинации.
- Пользовательские действия (клик, ввод, сабмит) — через testing-library, не через внутренний API компонента.
- Асинхронные состояния: loading → success / loading → error.

## Чего не делаем
- Не тестируем реализацию (внутренние методы, приватные состояния). Тестируем поведение.
- Не мокаем то, что можно не мокать. Чем ближе к реальному коду — тем надёжнее тест.
- Не дублируем e2e в юнитах и наоборот.
