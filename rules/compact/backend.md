# Backend — компактные правила (универсальные)

Стек (язык, фреймворк, БД, HTTP-клиент), test-инструменты и соглашения конкретного проекта — в `TECH-LEAD.md` (и `BACKEND.md`/`TESTING.md` если есть). Здесь — роль и дисциплина.

## Структура
- Каждый внешний сервис/домен — отдельный модуль.
- Entry-файл (`server.*`/`main.*`) — только роуты/middleware/bootstrap. Логика в модулях.
- Секреты и токены — из конфига/env/хедеров, не из кода.

## API
- Единый формат ответа: данные либо `{ error: "..." }` с корректным статусом.
- Валидация обязательных полей запроса до выполнения логики.
- Не проглатывай ошибки внешних API — пробрасывай осмысленное сообщение.

## Авторизация и секреты
- Токены никогда не логировать (включая полные тела запросов к внешним API).
- Никаких секретов в ответах/URL.

## Внешние API
- Таймауты — обязательно.
- Повторные/пакетные запросы к одному API делай последовательно, если API так требует (избегаем rate limit / ECONNRESET).
- Ошибки внешнего сервиса → понятное сообщение + статус, не 500 по дефолту.

## Тесты
Инструменты — из `TECH-LEAD.md` / `TESTING.md`. Обязательно для: парсеров и чистых функций, роутов с ветвящейся логикой, интеграций с внешними API (через моки), баг-фикса (регрессионный тест). Токены в тестах фиктивные. Скип/отключение падающих тестов — запрещено.

## Не делай
- Состояние в памяти сервера (если в проекте явно не указано иначе).
- `eval`, конкатенация строк для SQL/команд.
- `console.log` с токенами/PII.
