# ТЗ: AI-дашборд разработчика с интеграцией YouTrack, Figma и Claude Code

## Цель

Локальный инструмент для разработчика на маке. Показывает задачи из YouTrack в виде канбан-доски. На каждой карточке две кнопки: первая — Claude читает задачу и все комментарии и рассказывает что понял, вторая — Claude переключается на ветку и пишет код.

---

## Стек

- **Фронт:** Vue 3 (Vite)
- **Бэк:** Node.js + Express (локальный мостик между браузером и терминалом)
- **Пакетный менеджер:** npm

### server.js — endpoints

---

**GET /api/tasks**

- Обращается к YouTrack REST API
- Возвращает задачи назначенные на текущего пользователя
- Поля каждой задачи:
  - `id` — например PROJ-142
  - `title` — название задачи
  - `status` — статус задачи
  - `branch` — совпадает с `id` задачи (например `PROJ-142`)
  - `url` — прямая ссылка на задачу в YouTrack

> Комментарии и описание НЕ хранятся на бэке. Claude сам читает их напрямую из YouTrack когда нужно.

---

**POST /api/read-task**

Принимает: `{ taskId, taskUrl, projectPath }`

Формирует промпт для Claude:

```
Зайди по ссылке {taskUrl} в YouTrack (используй токен из переменной окружения YOUTRACK_TOKEN через YouTrack REST API).
Прочитай описание задачи и все комментарии.
Если в описании или комментариях есть ссылка на Figma — зайди туда через Figma API (токен FIGMA_TOKEN) и изучи макет.
После этого расскажи:
1. Что нужно сделать по задаче
2. Что говорят в комментариях (особенно тестировщик)
3. Если есть Figma — что там за макет
4. Что ты планируешь сделать
Пока только читай и анализируй, код не пиши.
```

Запускает в новом окне Terminal.app:

```bash
cd {projectPath} && claude "{промпт}"
```

Возвращает `{ success: true }`

---

**POST /api/write-code**

Принимает: `{ taskId, taskUrl, projectPath }`

Формирует промпт для Claude:

```
Задача {taskId}.
Ветка называется {taskId} (например PROJ-142).

1. Переключись на ветку {taskId}. Если ветки нет — создай её от main/master.
2. Зайди по ссылке {taskUrl} через YouTrack REST API, перечитай описание и все комментарии чтобы освежить контекст.
3. Если есть ссылка на Figma — зайди через Figma API и изучи макет.
4. Выполни задачу: напиши код, исправь баги, сделай вёрстку — всё что требуется.
5. После завершения скажи что именно было сделано и какие файлы изменены.
Коммит не делай — это сделает разработчик сам после проверки.
```

Запускает в новом окне Terminal.app:

```bash
cd {projectPath} && claude "{промпт}"
```

Возвращает `{ success: true }`

### youtrack.js

- YouTrack REST API v3
- Endpoint: `GET /api/issues?query=for:me&fields=id,summary,customFields`
- Авторизация: `Authorization: Bearer {YOUTRACK_TOKEN}`
- Маппинг статусов на колонки:
  - "In Progress", "Open" → "В работе"
  - "Reopened" → "На доработку"
  - "Fixed", "Verified" → "Готово"

### figma.js

- Figma REST API
- Авторизация: `X-Figma-Token: {FIGMA_TOKEN}`
- Токен передаётся Claude через переменную окружения при запуске терминала
- Claude сам делает запросы к Figma когда находит ссылку в задаче

### claude.js

- Находит путь к claude через `which claude`
- Открывает новое окно Terminal.app через AppleScript:

```applescript
tell application "Terminal"
  do script "cd {projectPath} && YOUTRACK_TOKEN=xxx FIGMA_TOKEN=yyy claude \"{промпт}\""
  activate
end tell
```

- Экранирует кавычки в промпте перед вставкой

## Фронтенд

### KanbanBoard.vue — главная страница

- Три колонки: **На доработку** | **В работе** | **Готово**
- Колонка "На доработку" — заголовок с красноватым оттенком
- Кнопка "Обновить" вверху — перезагружает задачи
- Скелетон при загрузке

### TaskCard.vue — карточка задачи

Содержит:

- **ID задачи** — кликабельный, открывает YouTrack в новой вкладке
- **Название задачи**
- **Кнопка 1: "Прочитать задачу"**
  - Вызывает POST /api/read-task
  - Пока идёт запрос: "Открываю..."
  - После: "Claude читает задачу в терминале ✓"
- **Кнопка 2: "Писать код"**
  - Вызывает POST /api/write-code
  - Пока идёт запрос: "Открываю..."
  - После: "Claude пишет код в терминале ✓"
- Обе кнопки при клике проверяют есть ли сохранённый путь к репозиторию. Если нет — показывают модалку.

### Модалка выбора репозитория

- Появляется если путь к репо ещё не сохранён
- Поле: "Путь к репозиторию" (например `/Users/name/projects/my-app`)
- Чекбокс "Запомнить путь" (сохраняет в localStorage)
- Кнопки: Отмена / Подтвердить

## Роли на проекте

В работе с любым проектом через этот дашборд участвуют пять ролей. Каждая роль — это отдельный «режим», со своими правилами в папке `rules/`. Одна задача обычно проходит через несколько ролей последовательно.

| Роль | Что делает | Главный файл правил |
|---|---|---|
| **PM** (продуктовый менеджер) | Смотрит продукт глазами пользователя, ведёт `PM.md`, предлагает задачи в терминах «что видит пользователь». В технику не лезет. Каждой предлагаемой задаче ставит `Специалист: frontend \| backend \| fullstack`. | `rules/pm.md` |
| **Tech Lead** (технический лид) | Анализирует код, ведёт `TECH-LEAD.md` (+ при необходимости `TESTING.md`), фиксирует политику тестов, предлагает задачи по тех. долгу. Каждой задаче ставит `Специалист: frontend \| backend \| fullstack`. | `rules/tech-lead.md` |
| **Frontend-разработчик** | Берёт задачи со специалистом `frontend` (или `fullstack`). Работает в `frontend/`: Vue-компоненты, стили, composables, клиентская логика. | `rules/frontend.md` |
| **Backend-разработчик** | Берёт задачи со специалистом `backend` (или `fullstack`). Работает в `backend/`: сервер, роуты, API-модули, интеграции. | `rules/backend.md` |
| **QA** | Проверяет результат перед сдачей — чек-лист фронта, чек-лист бэка, регрессия, воспроизведение багов. | `rules/qa.md` |

### Специализация задач
PM и Tech Lead при создании предлагаемых задач обязаны указывать поле `Специалист` (`frontend | backend | fullstack`). Это нужно, чтобы задача сразу ушла тому разработчику, который её подхватит, без лишнего раунда уточнений. Правила выбора значения описаны в `rules/pm.md` и `rules/tech-lead.md` в разделе «Поле „Специалист“».

### Какие файлы читать перед работой
| Ситуация | Файлы |
|---|---|
| Задач нет — нужно проанализировать проект и создать задачи | `rules/pm.md` |
| Нужно проанализировать проект технически: стек, архитектура, тех. долг | `rules/tech-lead.md` |
| Получил задачу, анализируешь что делать | `rules/pm.md` (смотри глазами пользователя) |
| Пишешь или правишь Vue-компоненты, стили, composables | `rules/frontend.md` |
| Пишешь или правишь сервер, API-модули, роуты | `rules/backend.md` |
| Завершил задачу, проверяешь результат перед сдачей | `rules/qa.md` |
| Задача `fullstack` — пишешь и фронт и бэк | `rules/frontend.md` + `rules/backend.md` + `rules/qa.md` |
| Делаешь любой коммит — задача из трекера или прямые правки вне задач | `rules/commits.md` |

Правила актуальны для **всех проектов**, которыми управляют через этот дашборд.  
Если в процессе работы замечаешь что правило устарело или неполно — обнови соответствующий файл. Если правило специфично для одного проекта — пиши его в `TECH-LEAD.md` или `PM.md` этого проекта, не в глобальные `rules/`.

## Важные детали

- Бэкенд на порту 3001, фронтенд на 5173
- В vite.config.js настроить proxy: `/api` → `http://localhost:3001`
- CORS на бэке разрешить для localhost:5173
- Токены НИКОГДА не передавать на фронт — только бэк знает о токенах
- Токены передаются Claude как переменные окружения при запуске команды в терминале
- Путь к claude определять через `which claude` при старте сервера
- Коммиты разработчик делает сам после проверки результата
