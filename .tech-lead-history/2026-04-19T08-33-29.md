## 3. Рекомендация по приоритету

Задача «[Tech Debt] Поднять Vitest и первый слой тестов» из run 3/4 после этого фикса становится выше по срочности, чем была. Аргумент: только что закрыта критическая security-находка, и она осталась без автоматической защиты от регресса. Минимальный скоуп, который закрывает именно этот пробел:

- `npm i -D vitest @vue/test-utils jsdom` + скрипт `"test": "vitest run"`, `"test:watch": "vitest"`.
- `src/utils/socialLinks.spec.ts` с кейсами:
  - `http://`, `https://`, `mailto:`, `tel:` — возвращаются как есть;
  - URL без схемы + `Email` → префикс `mailto:`;
  - URL без схемы + прочие лейблы → префикс `https://`;
  - `javascript:alert(1)`, `JavaScript:alert(1)`, ` javascript:alert(1)` (ведущие пробелы), `java\tscript:alert(1)`, `java\nscript:alert(1)` (control chars в схеме), `data:text/html,...`, `vbscript:msgbox`, `file:///etc/passwd` — все возвращают пустую строку;
  - пустой URL и URL из одних пробелов — пустая строка;
  - `getSocialLinkDisplayText` на тех же вредоносных входах — возвращает текст, не исполняемый код (контракт: функция только для отображения, экранирование — на стороне Vue).
- Fixture-корпус резюме из `docs/testing-strategy.md` — отдельной задачей, не блокирует этот минимум.

После появления спеки — снять устаревший пункт из `TECH-LEAD.md §7` и сослаться на `socialLinks.spec.ts` как на регрессионный guard.
