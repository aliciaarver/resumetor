# Resumetor — Tech Lead Review

- **Дата анализа:** 2026-04-19
- **Скоуп:** полный обзор (`TECH-LEAD.md` был пуст; за основу взяты `docs/adr/0001-*.md`, `docs/parser-pipeline.md`, `docs/testing-strategy.md`)
- **Тип проекта:** SPA-конструктор резюме. Полностью клиентский: парсинг PDF, форма, превью, PDF-экспорт. Бекенда нет.

## 1. Резюме состояния

Проект здоровый по инструментарию (Vue 3.5, Vite 8, TS 5.9 strict, Pinia 3) и уже имеет продуманную архитектурную декларацию (ADR-0001, parser-pipeline, testing-strategy). Основная проблема — **декларация опережает реальность**: целевая структура FSD-слоёв и разбивка парсера ещё не выполнены, из-за чего монолит парсера (`src/utils/parseTextToResume.ts`, 1940 строк) и толстый i18n-стор остаются точками высокого риска при изменениях. Тестов на данный момент нет вообще, хотя стратегия тестирования задокументирована. Есть одна реальная XSS-возможность в превью через поле URL.

Итог: доводка архитектуры до задекларированной и базовый слой тестов — ближайший приоритет, до этого крупные рефакторы парсера рискованны.

### Целевая структура по ADR-0001 (не выполнено)
```
app / pages / widgets / features / entities / shared
src/features/upload-resume/lib/{pdf-extraction, normalization, profile-detection,
  section-classification, entity-extraction}
src/features/upload-resume/model/{parse-resume-from-pdf.use-case, apply-confidence-fallback.use-case}
```
Из целевого выполнено только `entities/resume/*`. Всё остальное остаётся в «плоской» раскладке Vue-2-эпохи: `views`, `components`, `composables`, `utils` без деления на widgets/features/shared.

### Поток данных

```
File (PDF)
  └─ ResumeUploader → useResumeParser.parseFile
       ├─ extractPdfData (pdfjs-dist, lazy)
       │     normalizePdfPageText(items, width)  ← reading order + repair
       │     extractHeaderPersonalInfo (annotations, верхняя 25% страницы)
       │     extractPdfMetadata (Title/Author/Subject/Keywords)
       ├─ parseTextToResumeDetailed  ← монолит: секции + сущности + метрики
       ├─ buildPersonalMetrics / toConfidenceLevel / buildConfidenceNote
       ├─ applyConfidenceFallback   ← блоки с confidence=low не импортируются
       └─ buildParsedPdfMeta
         ↓
         ResumeStore.hydrateFromParsed  +  PdfMetaStore.hydrateFromParsed
         ↓
         ResumePreview (single source of truth — DOM с data-page-block)
         ↓
         measurePagedLayout(el)   ← общая пагинация и для превью, и для экспорта
         ↓
         usePdfExport.exportPdf → html2canvas(clone) → jsPDF.addImage по страницам
```

Это соответствует ключевому правилу ADR-0001: «`measurePagedLayout` — единственный движок разбиения страниц, превью и экспорт оба его потребляют». Архитектурно это правильно; риск в том, что движок — чисто DOM-измерительный и держится на атрибутах `data-page-block`/`data-page-block-kind`.

### Сторы

- `resume.ts` — тонкий контейнер: `ref<ResumeData>` + CRUD-методы коллекций (`addWorkExperience`, `removeSkill` и т.д.). Гидратация через `buildHydratedResumeData`. Соответствует ADR.
- `pdfMeta.ts` — state + watcher `syncFromResume` с флагом-защёлкой `synced`. Поле перезаписывается авто-значением только если оно пустое или совпадает с предыдущим авто-значением (`shouldSyncField`). Компактно.
- `locale.ts` — **жирный**, 550 строк. Содержит: два словаря сообщений RU/EN как литерал, `PROFICIENCY_ORDER`, мэппинг лейблов соц-ссылок, side-эффект на `document.documentElement.lang`. Прямо противоречит правилу ADR «сторы — тонкие state-контейнеры, не оркестрация».

## 4. Ключевые модули

### `utils/parseTextToResume.ts` (1940 LOC)
Эвристический парсер: определение профиля (`hh_ru` / `en_cv` / `generic`), классификация секций по scores, извлечение сущностей, измерение confidence. Сейчас это один файл — всё, что `parser-pipeline.md` планирует разнести на 5–7 модулей с явными контрактами. Без разбивки невозможно:
- независимо тестировать стадии (contract tests из testing-strategy);
- менять эвристики без риска каскадных регрессий;
- вводить новые профили парсеров (`single-column`, `two-column`, `dense-corporate`, `job-board-export`).

Заявленные в pipeline-документе профили — `single-column`/`two-column`/`dense-corporate`/`job-board-export`. В коде реально выбираются другие: `hh_ru`/`en_cv`/`generic`. **Это рассинхрон доки и кода.**

### `composables/useResumeParser.ts`
Оркестрирует парсинг, импортирует типы `ResumeBlockKey`/`ParseBlockMetrics` из `utils/parseTextToResume`. Это нарушает планируемую структуру (доменные типы confidence живут в `entities/resume/model/confidence.ts` и должны быть истиной в последней инстанции). Использует `any` для `pdfjs` объектов — понятная временная мера, но в safety-sensitive пути (URL из аннотаций PDF идут в превью как `href`).

### `composables/usePdfExport.ts`
Клонирует узел превью в оффскрин-контейнер, растеризует `html2canvas` (scale 2) и нарезает канвас по `pageStarts` в jsPDF. **Итоговый PDF — растр**, что прямо противоречит ATS-нарративу из UI (`pdf.hint` говорит пользователю, что меты «помогают ATS находить резюме»): ATS не прочитает картиночный текст, только встроенные Title/Subject/Keywords/Author. Это продуктово-технический конфликт — либо менять UI-копирайт, либо переходить на text-layer экспорт.

### `utils/pagination.ts`
`measurePagedLayout` обходит все `[data-page-block]` внутри корня и решает, переносить ли блок на следующую страницу. Учитывает только связку «heading + next block» (минимальный widow-control). Никакого `keep-together` для многострочных вакансий — крупная запись на границе страниц будет резаться. Не баг, но известное ограничение.

### `components/preview/`
- `ResumePreview.vue` (541 LOC) — активный шаблон `classic`.
- `ModernResumePreview.vue` (485 LOC) — **не зарегистрирован** в `utils/resumeTemplates.ts` (там только `classic`), в UI переключателя шаблонов также нет (`templateLabel`/`templateModern` переводы присутствуют, но селект не рендерится). Мёртвый код либо неоконченная фича.

## 5. Тех-долг и точки роста

### A. Архитектура / соответствие ADR

1. **Парсер — монолит.** `parseTextToResume.ts` на 1940 строк не разбит на стадии, описанные в `parser-pipeline.md`. Это главный источник будущих регрессий.
2. **FSD-слои не внедрены.** Есть только `entities/resume`. Нет `features/*`, `widgets/*`, `pages/*`, `shared/*`; `BuilderView.vue` — де-факто page + widget + feature-слой одновременно (515 LOC).
3. **`utils/` размыт.** Выполняет роль shared/infra: пагинация, нормализация текста, diff, флаги, соц-ссылки, эвристики парсера — всё в одной папке. Нужна миграция на `shared/lib`, `entities`, `features/upload-resume/lib`.
4. **Стор локализации нарушает «толщину».** `locale.ts` содержит полный словарь RU/EN и доменные мэппинги. По плану ADR сообщения должны уехать ближе к feature/entity.
5. **Рассинхрон терминологии профилей парсера.** В документации `single-column / two-column / dense-corporate / job-board-export`, в коде `hh_ru / en_cv / generic`. Одно из двух нужно исправить.

### B. Тестирование

6. **Тестов нет совсем.** `testing-strategy.md` предписывает unit / contract / integration / e2e, Vitest не подключён, фикстур нет. Для парсера это критичный долг — любое изменение эвристики изменяет поведение «на живую».
7. **Нет fixture-corpus.** `tests/fixtures/resume-corpus/` из testing-strategy отсутствует.

### C. Безопасность

8. **XSS через URL в соц-ссылках.** `utils/socialLinks.ts:buildSocialLinkHref` пропускает любой URL с известной схемой. `javascript:alert(1)` проходит регексп `/^[a-z]+:/i`, затем попадает в `<a :href>` внутри `ResumePreview.vue` и `ModernResumePreview.vue`. `rel="noreferrer"` не блокирует исполнение протокола. Нужен allow-list протоколов (`http`, `https`, `mailto`, `tel`).
9. **`any` в парсере PDF-аннотаций.** `useResumeParser.ts` приводит `pdf`, `annotation` к `any`. В комбинации с (8) ослабляет гарантии типов на пути, обрабатывающем внешние файлы.

### D. Надёжность / продукт

10. **Нет персиста черновика.** `ResumeStore` полностью in-memory. Рефреш страницы теряет все правки пользователя. `useLocalStorage` уже используется (`locale.ts`) — паттерн в руках.
11. **Экспорт — растр, а не текст.** ATS-обещание в UI не соответствует реальности. Либо `jsPDF.html()`/`pdf-lib` с текстовым слоем, либо переформулировать UI.
12. **`html2canvas` устаревает.** С распространением `oklch`, `color-mix`, modern gradients html2canvas 1.4.x парсит не всё. Средне-срочно стоит рассмотреть fork `html2canvas-pro` или альтернативу.
13. **Мёртвый `ModernResumePreview.vue`.** Либо зарегистрировать в `resumeTemplates.ts` и вывести селектор, либо удалить.
14. **Трещины в документации.** `README.md`, `docs/README.md`, `docs/adr/0001-*.md` линкуют файлы как `/Users/alicia/Desktop/⛤/resumetor/docs/…` — локальные абсолютные пути с глифом `⛤`, которые не работают ни в гит-хостинге, ни на текущей машине (каталог `xopa/`). Нужны относительные ссылки.

### E. Тулинг

15. **Нет ESLint / Prettier.** При TS strict и Vue 3 это необычно и заметно — нет машинной защиты стиля импортов, порядка объявлений, правил `vue/*`.
16. **Нет CI.** Даже минимального — lint + `vue-tsc --build` + vitest (когда появится). Push в main ничем не защищён.
17. **Нет precommit-хука.** Связанная с 15–16 дыра.
